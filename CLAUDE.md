# teyes-sibir-kod – сайт teyes-sibir.ru на коде

Перенос сайта Teyes Sibir с Tilda на код. Этап 1 – точная копия всех страниц Tilda (вёрстка, картинки,
скрипты) на GitHub Pages: https://tema-mail.github.io/teyes-sibir-kod/. Замысел – `docs/ЗАМЫСЕЛ.md`,
решения и журнал – `docs/РЕШЕНИЯ.md`, порядок сборки – `run.sh`.

## Стек и запуск
- Python 3 (стандартная библиотека + Pillow в `.venv/`, его создаёт `run.sh`) и `curl`, Chrome для проверки.
- `./run.sh` – полный пересбор копии: `pages.py` (страницы) → `assets.py` (ресурсы) → `images.py` (WebP)
  → `store.py` (снимок каталогов и лент) → ещё раз `assets.py` и `images.py` (обложки постов из лент)
  → `build.py` (`public/`) → `verify.py` (проверка).
  Адреса Tilda разбирает общий `tilda_urls.py`. Проверка выложенной копии: `verify.py --site <адрес>`.
- `public/` – готовый сайт, его выкладывает `.github/workflows/pages.yml`. `raw/` – сырьё, в git не идёт.
- Этап 2 (страницы на Astro, магазин из данных) – после разбора копии с владельцем.

## Границы
- В Tilda ничего не писать: только чтение (правило владельца – запись в Tilda только с его «да»).
- Копия закрыта от поиска (`meta robots noindex`): это дубль живого teyes-sibir.ru.
- Счётчики (Метрика, статистика Tilda, zrok.cloud) из копии вырезаются – иначе копия портит статистику сайта.
- Ключи (Tilda MCP и др.) – только в `~/.config/...`, в репозиторий не попадают.

## Правила работы
- Файл больше 800 строк не дописывать, а выносить новый модуль.
- Делать только то, о чём просили. Никаких попутных улучшений и лишних файлов.
- После каждого рабочего шага – коммит.
- Перед правкой прочитать те места, которых она касается, а не догадываться.
- Задача трогает больше трёх файлов кода – остановиться и предложить разбить.
- Чего не знаешь – спросить, а не подставить заглушку и не выдумать.
- Решение, записанное только в комментарии, не считается внедрённым: выбор
  модели, провайдера или настройки живёт в константе, которую код читает.
- Владелец сообщает о сбоях словами в чате и в файлы сам не пишет –
  записывать за ним.
